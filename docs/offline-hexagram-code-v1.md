# JingGua Offline Hexagram Code V1

状态：Pocket 固件与 Web 共用的离线确定性编码协议。编码在设备本地完成，不依赖 Wi-Fi、API、设备绑定或云端数据库。

## 查询入口

用户可在 <https://gua.overme.cn/> 输入设备显示的四位数字，以还原同一组六爻并复制 AI 解卦提示词。Pocket 只显示编码，不主动打开网页或发送网络请求。

## 输入与顺序

输入必须是六个完整爻值，顺序从下往上：

| i | 爻位 | 允许值 |
| ---: | --- | --- |
| 0 | 初爻 | 6、7、8、9 |
| 1 | 二爻 | 6、7、8、9 |
| 2 | 三爻 | 6、7、8、9 |
| 3 | 四爻 | 6、7、8、9 |
| 4 | 五爻 | 6、7、8、9 |
| 5 | 上爻 | 6、7、8、9 |

| 爻值 | 含义 | Base-4 数位 |
| ---: | --- | ---: |
| 6 | 老阴 | 0 |
| 7 | 少阳 | 1 |
| 8 | 少阴 | 2 |
| 9 | 老阳 | 3 |

编码直接使用六个完整爻值，不使用屏幕从上到下的绘制顺序、六十四卦序号、History ID、时间戳、随机数、MAC 或芯片 ID。

## 编码公式

令 `line_values` 为按初爻到上爻排列的六个数值：

```text
code = Σ((line_values[i] - 6) × 4^i), i = 0..5
```

因此初爻是最低位、上爻是最高位。有效输入的编号范围为 `0..4095`；显示必须为恰好四位十进制数字，左侧补零：

```text
0 → 0000
5 → 0005
740 → 0740
4095 → 4095
```

这个计算是 Base-4 的六位表示，共有 `4^6 = 4096` 种输入组合；每组组合得到唯一编号，且编号覆盖 `0000..4095` 全范围。6 和 9 是否动爻不会改变映射，编码仍保留完整的六个爻值。

## 固定测试向量

```text
line_values = [6, 7, 8, 9, 8, 6]
Base-4      = [0, 1, 2, 3, 2, 0]
code        = 0×1 + 1×4 + 2×16 + 3×64 + 2×256 + 0×1024
            = 740
显示         = 0740
本卦         = 第40卦 雷水解
动爻         = 初爻、四爻、上爻
变卦         = 第41卦 山泽损
```

边界向量：六个老阴 `[6,6,6,6,6,6] → 0000`；六个老阳 `[9,9,9,9,9,9] → 4095`。

## 固件与历史记录

Pocket 使用 `Yao::coins.total`，即 `DivinationSession` 中初爻到上爻的内部顺序作为输入。只有六爻与 `DivinationResult` 均已完成后才显示 `CODE NNNN`。当前历史记录已保留六个 `lineTotals`，重新显示历史记录时从这六个值重新计算，不额外持久化编码或改变 History schema。

## 兼容性与未来版本

V1 的名称、数值映射、爻序、公式和四位十进制显示是固定协议。修 bug 或调整 UI 不得改变任何 V1 编码。若未来确需不同语义，必须定义独立的 V2（包含显式版本识别），并在迁移期继续支持 V1；不得静默复用或重新解释 V1 编号。Web 与 Pocket 在发布前应对固定向量和 4096 组合测试保持一致。
